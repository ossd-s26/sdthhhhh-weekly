### Cathedral vs Bazaar and AI

This week we learned about the cathedral and bazaar models of development. The cathedral model is more structured, where a small group of developers carefully design and control the project. In contrast, the bazaar model is more open, where many contributors can participate and the development process is more decentralized.

Personally, I feel that many modern open source projects follow the bazaar model, but still keep some structure like the cathedral model. For example, even though anyone can contribute, maintainers still review pull requests and make final decisions. So it is more like a combination of both.

<!--more-->

With the development of AI tools that can help write code, I think the bazaar model may become even more active. More people can contribute because AI lowers the barrier to entry. However, this also creates challenges, because maintainers need to review more contributions and make sure the quality is still high. AI can help generate code, but understanding the code and making good design decisions is still important.

### Observations on Other Groups

After reading reports from other groups, I noticed that many groups are facing similar challenges. One common issue is communication with maintainers, since responses are not always immediate.

At the same time, it was interesting to see the different types of projects that other groups chose. Some groups are working on very technical problems, while others focus more on documentation or UI improvements. This shows that there are many different ways to contribute to open source projects.
